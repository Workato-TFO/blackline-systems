Phase 1

Optimize the recipe

In this phase, you'll measure a working recipe, then reduce its job duration and task count.

Pattern

Measure, optimize, re-measure

Record the duration and task count before you change anything, then change the recipe and measure again, so you can show the change helped instead of assuming it did.

1.1

Set up the recipe and measure the baseline

With the first recipe in good shape, management thinks other recipes use more resources than they need. Jordan inherits another team's recipe, which emails a report of Salesforce Contacts and Account data. It works, but a job uses about 97 tasks and takes around 15 seconds.

Overview

You'll open the report recipe in your project, connect it to your Salesforce instance and set the email address for the report. Then you'll run it unchanged and note the job duration and total tasks. Those numbers are your baseline.

Detailed steps 4 steps

Optimization needs a starting point. The recipe already produces the right report, so the only thing that can improve is how much time and how many tasks it takes. The baseline is what you compare against in the next task.

  • Open the report recipe in your project, the one that started as Recipe Optimization | Start.

  • Select your Salesforce connection in the recipe, so it points to your instance.

  • Change the report's recipient email address to your own.

  • Test the recipe without any changes, and note the job duration and the total tasks used. Expect about 97 tasks and around 15 seconds.

Verify you have recorded the job duration and total tasks from the unchanged run.

1.2

Optimize the recipe

The recipe returns the right report, but each job takes longer as the number of Contacts grows, and every extra task counts against resources. The design was never built for scale, so the recipe needs rework.

Overview

You'll rework the recipe so it runs faster and uses fewer tasks, while it still emails the same report. Then you'll test it again and compare the result with your baseline.

Detailed steps 2 steps

The recipe's working behavior stays the same. The goal is a shorter job and fewer tasks.

  • Optimize the recipe to run faster and use fewer tasks. Aim for the best result you can; an optimized version can use fewer than 10 tasks.

  • Test the recipe again and compare the job duration and total tasks used with your baseline.

Verify the optimized recipe uses fewer tasks in a test run than it did before.

Reflect

Now that you've optimized a recipe, consider how you would apply this to the recipes your team already runs.

  • Why does a recipe need to be measured before it is changed, and which two numbers did you record?
  • Which changes to the recipe lowered the job duration, and which lowered the total tasks used?
  • What would the report job cost as the number of Contacts keeps growing, and how would you check?

Wrap-up

Jordan's report recipe delivers the same output as before, with a shorter job duration and fewer tasks. That completes Jordan's path from an untidy recipe to a project the team can read, trust and run efficiently.

  • Measure, change, re-measure. Record the duration and task count first, then compare after each change.
  • Fewer tasks, same result. A well-structured recipe can produce the same report in a fraction of the tasks.
  • Optimize for scale. A recipe that works for today's Contacts can slow down as the count grows, so design for the volume you expect.
