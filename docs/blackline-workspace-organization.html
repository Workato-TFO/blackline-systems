1.1

Organize the project by asset type

The refactored recipe is readable, but it still sits beside its functions, the report recipe and the connections in one personal project. A teammate hunting for the Salesforce connection has to open items one by one.

Overview

You'll reorganize your personal project into folders for recipes, connections, functions and tags. Each asset takes the asset code for its type from the lookup table.

Detailed steps 4 steps

Naming and folder structure keep a project readable after its original builder moves on. Each asset code gives a type its own short label, so the type shows in the name before anyone opens the asset. Your project holds the recipe, its two functions, the report recipe and your connections, so every one of them gets a code.

  • Set up a folder structure in your personal project for recipes, connections, functions and tags.

  • Move each asset into the folder for its type. That includes the refactored recipe, both functions, the report recipe (Recipe Optimization | Start) and your connections.

  • Add the asset code for each asset's type, from the lookup table above, to the asset's name. Keep the name you already gave it.

  • Revisit the lookup table whenever you add an asset, so each new asset follows the same practices.

Verify each asset in your project carries the asset code for its type from the lookup table.

Reflect

Now that you've organized a project by asset type, consider what this means for a team that adds new recipes every week.

  • Which asset in your project was hardest to place, and what does that say about the folder structure?
  • The table lets you add R, W or RW to a connection code. When would a teammate need to see read or write access in the name before opening the connection?
  • What would you check first to see whether a new teammate is following the naming convention?

Wrap-up

Jordan's project now has a folder and a code for every asset type, so a teammate can find the Salesforce connection or a particular recipe without opening anything. Next, Jordan adds error handling to the recipe.

  • Asset codes as a shared vocabulary. A short code per asset type shows what an asset is before anyone opens it.
  • Folders by asset type. Separate folders for recipes, connections, functions and tags keep each kind of asset in one predictable place.
  • Access level in the name. The lookup table also lets you add R, W or RW to a connection code, so a teammate can see read or write access without opening the connection.
