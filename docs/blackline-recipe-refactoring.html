Phase 1

Refactor the recipe

In this phase, you'll split a working recipe into recipe functions and apply the naming, description and comment conventions.

Pattern

Recipe functions by business object

Each business object gets its own recipe function, so a change to one object stays in one place and the main recipe reads as a short sequence of calls.

1.1

Split the upserts into recipe functions

Jordan's inherited recipe already upserts the customer loan CSV into Salesforce correctly. The Account logic and the Contact logic both sit in the main recipe, so even a small change means reading all of it.

Overview

You'll refactor the recipe in Recipe Development | Start. The Salesforce Account upsert and the Contact upsert each move into their own recipe function. The main recipe parses the CSV and calls both. The processing logic stays the same.

Detailed steps 6 steps

This task turns a working recipe into a maintainable one that keeps the same behavior. Each function owns one object's check, update and create logic. The main recipe shrinks to a trigger, a parse and two calls.

  • Open Recipe Development | Start in your personal project. It runs every 60 minutes, parses a CSV file from File Storage and upserts the data to Salesforce. File Storage works like Google Drive or Box.

  • Find the sample CSV in File Storage at /Workshop Assets/Lab Files/Recipe Development/Customer Loan Data/customer_loan_data_usa.csv. You'll use it to test your copy of the recipe.

  • Move the Salesforce Account upsert logic into its own recipe function.

  • Move the Salesforce Contact upsert logic into its own recipe function.

  • In the main recipe, call the Account function and then the Contact function after Parse CSV.

  • Test the recipe with the sample CSV. The processing logic must stay the same.

Verify the main recipe calls one recipe function for the Account upsert and one for the Contact upsert.

1.2

Apply the best-practice conventions

The refactored recipe runs, but a teammate opening it next quarter still has to read every step to learn what it does and why. Jordan wants names, descriptions and comments that answer that before anyone opens a step.

Overview

You'll apply the best practices you have learned to the recipe and both functions. That covers naming conventions, descriptions, step comments and formula comments. The recipe's behavior does not change.

Detailed steps 4 steps

Names, descriptions and comments let a reader understand a recipe without running it. You'll apply the same conventions to the main recipe and to each function, so all three read alike.

  • Rename the recipe and both functions to follow the recipe naming conventions you have learned. A later lab adds asset codes to these names.

  • Add a description to the recipe and to each function.

  • Add a comment to every step.

  • Add a comment to every formula.

Verify every step in your recipe has a comment.

Reflect

Now that you've split a working recipe into recipe functions, consider what this means for the next developer who inherits it.

  • Which part of the original recipe would have been hardest to change safely before the split, and what made it hard?
  • Each function in the diagram checks whether a record exists before it updates or creates one. What would change if that check lived in the main recipe instead?
  • Which naming convention or comment would help you most if you reopened this recipe in six months, and why?

Wrap-up

Jordan's recipe still does the same job, but the Account and Contact logic now sit in separate functions with names, descriptions and comments that a teammate can read without running them. Next, Jordan files and names every asset in the project.

  • Recipe functions by object. Give each business object its own function, and a change to one object stays inside one function.
  • Names, descriptions and comments. One convention across the recipe and its functions keeps each part readable at a glance.
  • A short main recipe. When functions hold the detail, the main recipe reads as a trigger, a parse and a sequence of calls.
